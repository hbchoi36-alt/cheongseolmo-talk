# 청설모 Talk 결과 파일 만들기 요청문 (Claude 웹 채팅용)

---

## 📌 운영자용 사용 방법 (사람이 읽는 부분)

앱의 AI 분석을 쓸 수 없을 때, Claude 웹 채팅(claude.ai)으로 결과 파일(.json)을 만들어 앱에서 불러오는 비상 방법이에요.

1. claude.ai에서 **새 채팅**을 열어요.
2. **이 문서**와 **설문 결과 CSV 파일**(구글폼에서 받은 파일, .zip이면 압축을 푼 CSV)을 함께 첨부해요.
3. 메시지에 분석할 문항을 적어 보내요. 예:
   > 첨부한 요청문대로, CSV의 "앞서 개선이 필요하다고 응답한 분야와 관련하여 그렇게 생각하게 된 구체적 경험이나 사례를 말씀해주세요." 열을 분석해서 결과 파일을 만들어 줘.
   - 문항 제목은 CSV 맨 윗줄에 있는 그대로 복사해 붙이면 가장 정확해요. "2번째 문항"처럼 써도 돼요.
4. Claude가 만든 결과를 `.json` 파일로 저장해요.
   - 파일로 내려받을 수 있게 주면 그대로 내려받아요.
   - 글로만 주면: 코드 상자 안의 내용을 모두 복사 → 메모장에 붙여 넣기 → [다른 이름으로 저장] → 파일 이름 끝을 `.json`으로, 인코딩은 **UTF-8**로 저장해요.
5. 앱 시작 화면의 **[🌳 저장한 결과 파일 불러오기]**로 그 파일을 올려요.
   - "결과 파일이 올바르지 않아요 — (이유)"가 나오면, 그 이유를 채팅에 그대로 붙여 넣고 "이 문제를 고쳐서 다시 만들어 줘"라고 요청해요.
6. 생각나무가 뜨면, **이름이 ●●로 가려졌는지·욕설이 순화됐는지** 도토리를 눌러 훑어보고, 필요하면 [✏️ 고치기]로 다듬은 뒤 [⬇ 결과 파일 내려받기]로 다시 저장해요.

> ⚠️ 웹 채팅에 CSV를 올리는 것도 직원 의견을 외부(Anthropic)로 보내는 일이에요. 실제 직원 의견이라면 기관 보안 검토를 먼저 받고, 사용하는 계정의 데이터 처리 설정을 확인해 주세요.

## 🤖 Claude에게 보내는 요청 (여기부터 Claude가 따를 내용)

당신은 간담회 사전 설문 의견을 분석해 **청설모 Talk** 앱이 불러올 수 있는 **결과 파일(JSON)** 을 만드는 역할을 합니다. 앱은 이 파일을 불러올 때 아래 규칙을 자동으로 검사하고, 하나라도 어기면 파일을 거부합니다. 규칙을 반드시 모두 지켜 주세요.

### 1. 입력
- 첨부된 CSV 파일 하나. 첫 줄은 열 이름(문항 제목)이고, 둘째 줄부터 응답자 한 명당 한 줄입니다.
- 분석할 열은 **사용자가 메시지로 지정한 열 하나**입니다. 지정되지 않았거나 어느 열인지 애매하면, 만들기 전에 열 이름 목록을 보여 주고 물어보세요.
- 다른 열(타임스탬프, 체크박스 문항 등)은 분석에 쓰지 않습니다.

### 2. 의견 정리
- 지정한 열의 칸을 위에서부터 차례로 봅니다.
- **빈칸과 공백만 있는 칸은 뺍니다.** 나머지는 모두 유효 의견입니다 (하나도 빼지 않습니다).
- 유효 의견에 위에서부터 **1, 2, 3, …** 번호를 매깁니다 (빈칸은 번호를 건너뛰지 않고 아예 세지 않음).

### 3. 화면용 문장 (`displayText`) — 원문을 바꾸지 않는 것이 원칙
- 기본은 **원문 그대로** 씁니다. 맞춤법을 고치거나 줄이거나 다듬지 않습니다.
- 예외는 두 가지뿐입니다.
  1. **사람 이름**은 `●●`로 바꿉니다 (예: "김민수 과장님이" → "●● 과장님이"). 직급·직책은 남깁니다.
  2. **욕설·공격적 표현**이 있는 의견은 뜻을 살려 정중하게 순화한 문장으로 바꾸고 `"softened": true`로 표시합니다. 그 밖의 의견은 `"softened": false`입니다.
- 순화한 의견도 주제 분류와 건수에는 그대로 포함합니다.

### 4. 주제 나누기 (`topics`)
- 주제는 의견을 보고 정하되, **'기타'를 포함해 최대 7개**입니다.
  - 주제가 7개를 넘을 것 같으면 **의견 수가 적은 주제부터 '기타'로 합칩니다.** 어느 주제에도 맞지 않는 의견도 '기타'에 넣습니다. '기타'가 필요 없으면 만들지 않아도 됩니다.
- **모든 유효 의견은 적어도 한 주제에 들어가야 합니다 (누락 0건).**
- 한 의견이 여러 주제에 해당하면 해당하는 주제마다 모두 넣습니다 (주제마다 건수에 셈). 단, **한 주제 안에 같은 번호를 두 번 넣지 않습니다.**
- 의견이 0건인 주제는 만들지 않습니다.
- 주제마다 다음을 씁니다.

| 항목 | 규칙 |
|---|---|
| `name` 주제 이름 | **1~10자** (띄어쓰기 포함), 다른 주제와 같은 이름 금지. 의견 수가 적은 주제를 모은 주제의 이름은 정확히 `기타` |
| `summary` 요약 | **1~100자**, 주제마다 1개. 그 주제 의견들의 핵심을 해요체 한 문장으로 |
| `discussionQuestions` 토론 질문 | **최대 3개**, 빈 질문 금지. 간담회에서 함께 이야기할 수 있는 열린 질문 |
| `opinionIds` 의견 번호 | 그 주제에 속한 의견 번호 목록 (2절에서 매긴 번호) |

- **주제 이름·요약·토론 질문에는 사람 이름을 쓰지 않습니다.**
- `topics` 순서는 의견이 많은 주제부터 쓰고, '기타'는 마지막에 둡니다.

### 5. 출력 형식
아래 형식과 **똑같은 칸 이름**으로, JSON만 담은 `.json` 파일을 만들어 주세요. 파일을 만들 수 없으면 코드 상자(```json) 하나에 JSON 전체만 담아 주세요. 칸을 더하거나 빼지 마세요.

```json
{
  "version": 1,
  "createdAt": "2026-10-28T10:30:00Z",
  "sourceFileName": "googleform-export.csv",
  "opinions": [
    { "id": 1, "displayText": "부서 내 업무분장 기준이 명확하지 않아 …", "softened": false },
    { "id": 2, "displayText": "●● 과장님이 퇴근 직전에 업무를 …", "softened": false },
    { "id": 3, "displayText": "회의 분위기가 위축되어 의견을 말하기 어려워요.", "softened": true }
  ],
  "topics": [
    {
      "name": "업무 효율화",
      "summary": "업무분장 편중과 반복 보고를 줄여 달라는 의견이 많았어요.",
      "discussionQuestions": ["가장 먼저 줄이고 싶은 반복 업무는 무엇인가요?"],
      "opinionIds": [1, 2]
    },
    {
      "name": "기타",
      "summary": "회의 분위기처럼 의견 수가 적은 주제를 모았어요.",
      "discussionQuestions": [],
      "opinionIds": [3]
    }
  ]
}
```

- `version`: 항상 숫자 `1`
- `createdAt`: 만든 시각, ISO 형식에 시간대까지 (예: `2026-10-28T10:30:00Z` 또는 `2026-10-28T19:30:00+09:00`)
- `sourceFileName`: 첨부된 CSV 파일 이름
- `opinions`: 2절의 모든 유효 의견을 번호 순서대로. `id`는 숫자, `softened`는 `true`/`false`
- 위 예시의 내용은 형식 설명용입니다. 실제 내용은 첨부 CSV로 채워 주세요.

### 6. 내보내기 전 스스로 확인
JSON을 주기 전에 아래를 하나씩 확인하고, 마지막에 결과를 짧게 알려 주세요.
- [ ] 유효 의견 수 = `opinions` 개수, 빈칸 수도 함께 알려 주기
- [ ] 모든 의견 번호가 적어도 한 주제에 들어 있음 (누락 0건)
- [ ] 주제 7개 이하, 이름 1~10자·중복 없음, 요약 1~100자, 질문 3개 이하·빈 질문 없음
- [ ] 한 주제 안에 같은 번호 없음, 의견 0건인 주제 없음, 없는 번호 없음
- [ ] 이름을 `●●`로 바꾼 의견 수, 순화한 의견 수
- [ ] 주제 이름·요약·질문에 사람 이름 없음
- [ ] JSON 문법이 맞음 (쉼표·따옴표·괄호)
